# 数据库选型记录

## 现状

- 业务数据：SQLite（aiosqlite + SQLAlchemy），文件路径 `./data/app.db`
- 向量数据：ChromaDB，持久化目录 `./data/chroma_db`

---

## 业务数据库方案对比

| 方案 | 优点 | 缺点 | 适用阶段 |
|------|------|------|---------|
| **SQLite**（现状） | 零配置、无需独立服务、运维成本极低、文件即数据库方便备份 | 并发写入锁表、不支持多实例、不支持网络访问 | 早期/单机/用户量 <1000 |
| **PostgreSQL** | 高并发、行级锁、支持多实例、生态成熟、SQLAlchemy 兼容 | 需独立服务、运维成本增加、需迁移数据 | 用户量增长后 |
| **MySQL** | 高并发、社区成熟 | 与 SQLAlchemy async 支持略逊于 PostgreSQL、JSON 支持较弱 | 团队已有 MySQL 经验时 |

**结论：** 业务数据库升级路径为 SQLite → PostgreSQL，迁移成本低（仅改 `DATABASE_URL`）。

---

## 向量数据库方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **ChromaDB**（现状） | 嵌入式、零配置、Python 原生、易于集成 | 无分布式、性能上限低、不适合大规模 | 向量数量 <100 万，单机 |
| **pgvector** | 与 PostgreSQL 合并一库、运维最简、支持混合查询（业务数据 + 向量） | 性能弱于专用向量库、向量维度有上限（2000） | 中等规模，已使用 PostgreSQL |
| **Qdrant** | 高性能、支持复杂过滤查询、REST API 友好、Rust 实现资源占用低 | 需独立部署、引入新服务 | 中大规模，对过滤查询有需求 |
| **Milvus** | 分布式、支持十亿级向量、功能最全 | 重量级、部署复杂、资源消耗大 | 超大规模生产环境 |
| **Weaviate** | 内置多模态支持、GraphQL 查询 | 配置复杂、资源占用较大 | 有图文混合检索需求 |

**结论：** 向量库升级路径为 ChromaDB → pgvector → Qdrant/Milvus，按需分阶段迁移。

---

## 综合升级路径

1. **当前阶段**（✅ 现状）：SQLite + ChromaDB，适合早期单机运行
2. **第一次升级**（并发遇到瓶颈 / 需多实例）：迁移到 **PostgreSQL + pgvector**，一步到位，运维最简
3. **第二次升级**（向量数量 >100 万 / 检索性能下降）：向量库迁移到 **Qdrant**，业务库保持 PostgreSQL
4. **大规模生产**（千万级向量 / 多机集群）：向量库升级到 **Milvus**

**触发升级的信号：**
- SQLite：单机并发写入报错、需要多实例部署、数据库文件超过 5GB
- ChromaDB：向量检索响应超过 500ms、向量数量接近 100 万
