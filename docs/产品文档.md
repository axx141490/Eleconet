## 1. 产品概述

RAG 智能知识库是一套基于 **检索增强生成（Retrieval-Augmented Generation）** 技术的 SaaS 知识管理平台。

用户将文档上传至知识库后，系统自动完成文本解析、分块、向量化，并将向量索引存入 ChromaDB。提问时，系统先语义检索最相关的文档片段，再将其作为上下文送入 LLM，最终返回带来源引用的精准回答。

### 核心价值

| 维度 | 描述 |
|------|------|
| 多格式解析 | 覆盖文本、PDF、Office、图片、音视频共 20+ 格式 |
| 多模型支持 | OpenAI、DeepSeek、通义千问、智谱、Ollama，运行时切换 |
| 商业化能力 | 三级订阅套餐、微信/支付宝支付、知识库市场 |
| 灵活部署 | Docker 一键启动，支持私有化部署，数据不出内网 |
| 访客体验 | 分享链接无需注册即可体验问答 |

### 2.3 文档上传与处理

#### 支持格式

| 类别 | 扩展名 | 解析方式 |
|------|--------|---------|
| 纯文本 | `.txt` `.md` `.csv` `.json` `.log` `.xml` `.yaml` `.yml` | 直接读取 |
| PDF | `.pdf` | PyMuPDF / pdfplumber |
| Word | `.docx` `.doc` | python-docx |
| Excel | `.xlsx` `.xls` | openpyxl / pandas |
| PowerPoint | `.pptx` `.ppt` | python-pptx |
| 图片（OCR） | `.png` `.jpg` `.jpeg` `.gif` `.bmp` `.webp` | Tesseract / 百度 OCR / Vision |
| 音频 | `.mp3` `.wav` `.m4a` `.ogg` `.flac` | OpenAI Whisper 语音转录 |
| 视频 | `.mp4` `.avi` `.mkv` `.mov` `.wmv` `.webm` | FFmpeg 提取音轨 → Whisper |

#### 处理流程

```
上传文件
  → 格式识别（ParserFactory）
  → 文本提取（对应 Parser）
  → 文本分块（chunk_size=1000，overlap=200）
  → Embedding 向量化（LLM Provider）
  → 存入 ChromaDB
```

处理状态：`pending → processing → completed / failed`，前端实时显示进度。

#### OCR 双引擎

| 引擎 | 场景 |
|------|------|
| Tesseract（本地） | 离线部署，无需外部 API |
| 百度 OCR（API） | 精度更高，需配置 API Key |

### 2.4 智能问答（RAG）

#### 问答流程

```
用户提问
  → ChromaDB 语义检索（top_k=5）
  → 拼接检索结果 + 最近 6 条对话历史
  → 调用 LLM 生成回答
  → 返回答案 + 来源引用（[Document N] 格式）
```

#### 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| top_k | 5 | 检索文档块数量 |
| temperature | 0.7 | 生成多样性 |
| max_tokens | 2000 | 最大回答长度 |
| 历史对话 | 最近 6 条 | 上下文窗口 |

#### 特性

- **流式输出**：SSE 协议，实时打字机效果，减少等待感
- **多轮对话**：每次提问自动携带上下文历史
- **来源引用**：回答末尾标注引用自哪个文档
- **语言自适应**：回答语言自动跟随提问语言

### 架构亮点

**1. Provider 抽象层（最核心的设计）**

所有 LLM 和 Embedding 调用统一走 `llm_provider.py`，利用 OpenAI SDK 的兼容接口统一 6 家服务商（OpenAI / DeepSeek / 智谱 / 通义 / Ollama / 自定义），切换 Provider 只需修改 JSON 配置，无需改业务代码。

**2. RAG Pipeline 分层清晰**

```
上传 → Parser → TextChunker（段落→句子→字符三级分割，带 overlap）
     → VectorStore.add_chunks（批次 10 写入）
     → 查询时 semantic search top-k → 构建 context → LLM → SSE 流式输出
```

**3. 多格式 Parser 工厂模式**

`parser_factory.py` 按扩展名路由到对应 Parser，新增格式只需继承 `BaseParser` 并注册，解耦良好。

**4. OCR 双通道兜底**

图片解析优先走百度 OCR（精度高），失败或未配置则降级 Tesseract，保证可用性。

**5. 大文件音视频处理**

视频先用 ffmpeg 提取音轨，音频 >25MB 时自动按 600s 切段分批调用 Whisper API（规避接口限制），段落拼接还原完整转录。

---

### 实现难点

**1. 多 Provider Embedding 一致性**

不同 Provider 的 Embedding 维度和空间不同，向量库一旦用 A 模型写入就不能用 B 模型检索。切换 Provider 后旧的 ChromaDB collection 会失效，需要重新向量化文档——这是目前潜在的运维风险点。

**2. SSE 流式 + 来源引用的时序问题**

`query_stream` 先流式输出 answer token，最后再 yield sources 和 done 事件。前端需要正确处理这个异步序列，在打字机效果结束后才展示来源引用。

**3. 分块策略的语义完整性**

Chunker 采用段落→句子→字符的三级分割并保留 overlap，目的是避免在句子中间截断导致语义丢失，但 overlap 会造成同内容在多个 chunk 重复，召回时需过滤相似度极高的重复结果。

**4. 无 UI 框架的前端复杂度**

纯原生 CSS 手写整套响应式布局、模态框、流式打字机动效、多状态表单，代码量和维护成本比使用组件库高，但包体积小、样式可控。

**5. 套餐限制与访客隔离**

分享链接需要在无登录态下鉴权知识库归属、套餐等级、链接有效期三个维度，GuestChat 路由需单独处理这套逻辑，与主认证体系并行维护。

## 4. 快速开始

### 前置依赖

| 依赖 | 说明 |
|------|------|
| Docker >= 20.x | 容器运行时 |
| OpenAI API Key | 或其他兼容服务商的 Key |
| ffmpeg（可选） | 视频文件处理 |
| tesseract（可选） | 本地 OCR |

### Docker 启动（推荐）

```bash
# 1. 克隆仓库
git clone <repo-url>
cd rag-knowledge-base

# 2. 配置环境变量
cp backend/.env.example backend/.env
# 编辑 backend/.env，至少填入 OPENAI_API_KEY 和 SECRET_KEY

# 3. 启动
docker compose up -d --build

# 访问
# 前端：http://localhost:3000
# API 文档：http://localhost:8000/docs
```

### 仅重启（代码更新后）

```bash
# 只改了后端 Python 代码
docker compose restart backend

# 只改了前端代码
docker compose restart frontend

# 前后端都改了
docker compose restart backend frontend

# 改了 Dockerfile 或依赖文件才需要 rebuild
docker compose up -d --build
```

### 本地开发启动

```bash
# 后端
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000

# 前端（新终端）
cd frontend
npm install
npm run dev
```

## 8. 已知限制

| 限制 | 影响 | 缓解方案 |
|------|------|---------|
| SQLite 单机架构 | 不支持横向扩展 | 升级路径为 PostgreSQL + pgvector |
| 文档处理为串行 | 高并发上传时排队 | 引入 Celery + Redis 异步任务队列 |
| 切换 Embedding 模型 | 已有向量索引失效 | 切换后需重新上传文档 |
| 音视频转写速度 | ARM 架构下 Whisper 较慢 | 使用更小的模型（tiny/base）或接入 Whisper API |
| 分享链接有效期 | 固定 1 小时 | 后续支持自定义有效期 |
